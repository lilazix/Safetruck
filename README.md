1. ПОЧЕМУ ПРОЕКТ ХОРОШО СОВПАДАЕТ С ТЕМОЙ
═══════════════════════════════════════════════════════════════════════════════

Тема дипломной работы предполагает две ключевые составляющие:
  (1) интеллектуальный мониторинг транспорта (телематика, карты, алерты, отчёты);
  (2) защита телематических и персональных данных.

SafeTrack реализует обе части в одном веб-приложении:

  • Мониторинг транспорта:
    — Учёт транспортных средств и водителей, привязка водителя к ТС.
    — Приём и отображение телематических данных: координаты, скорость, топливо,
      зажигание, одометр (в учебной постановке данные генерируются скриптом).
    — Карта с позициями ТС в реальном времени, история поездок и треки.
    — Дашборд со сводкой: онлайн/офлайн, алерты за день, быстрые переходы.
    — Алерты: превышение скорости, резкое торможение, низкое топливо, простой
      с зажиганием, выход из геозоны, перегрев и др.
    — Отчёты: пробег, топливо, алерты, экспорт с учётом прав доступа.

  • Защита телематических данных:
    — Шифрование чувствительных полей в БД (VIN, номер водительского удостоверения),
      маскирование при отображении.
    — Роли и разграничение доступа: администратор, диспетчер, наблюдатель;
      экспорт отчётов только при наличии права.
    — Аудит: лог доступа (кто экспортировал данные, кто менял роли, кто удалял данные).
    — Политика хранения данных: настраиваемые сроки, автоматическое удаление
      устаревшей телеметрии и алертов (команда apply_retention_policies).
    — Двухфакторная аутентификация (2FA, TOTP) для усиления безопасности учётных записей.
    — Безопасный приём данных: API с ключом (X-API-Key), без доступа для обычных пользователей.
    — Страницы «Политика конфиденциальности» и «Защита данных» — прозрачность обработки.

Таким образом, проект не просто «сайт про машины», а целостная система, в которой
и мониторинг, и защита данных являются равноправными и реализованными частями,
что полностью соответствует формулировке темы диплома.

2. ФУНКЦИОНАЛЫ ПРОЕКТА (ПЕРЕЧЕНЬ)
═══════════════════════════════════════════════════════════════════════════════

  • Главная страница (лендинг)
    — Описание системы, навигация, вход и регистрация.

  • Регистрация и вход / выход
    — Создание учётной записи, аутентификация, поддержка 2FA (TOTP).

  • Двухфакторная аутентификация (2FA)
    — Настройка TOTP в профиле, проверка кода при входе, отключение 2FA.

  • Дашборд
    — Сводные виджеты: количество ТС, онлайн/офлайн, алерты за сегодня,
      последние события; ссылки на карту, транспорт, алерты, отчёты.

  • Карта
    — Отображение позиций ТС по последней телеметрии (маркеры на карте),
      выбор ТС, центрирование.

  • Транспорт (список ТС)
    — Таблица с гос. номерами, типом, маркой/моделью, статусом онлайн/офлайн,
      количеством алертов за день; поиск, фильтры по типу и статусу, сортировка, пагинация.

  • Карточка ТС (детальная страница)
    — Основные данные: тип, марка, модель, VIN (маскированный), объём бака, год, активность.
    — Текущее состояние из телеметрии: координаты, скорость, топливо, одометр, время обновления.
    — Блок «Водители»: список назначенных водителей, назначение существующего водителя,
      создание нового водителя с автоматическим назначением на это ТС, отвязка водителя.
    — Последние алерты по ТС; ссылки: на карту, отчёты, поездки, список ТС.

  • Добавление / редактирование / удаление ТС
    — Формы для создания и изменения ТС (гос. номер, тип, марка, модель, VIN и т.д.),
      подтверждение удаления.

  • Алерты
    — Список алертов с фильтрами (дата, ТС, тип, статус), отображение времени, ТС,
      типа, описания, статуса (новый/просмотрен/закрыт).

  • Отчёты
    — Выбор типа отчёта и параметров (период, ТС), формирование отчёта (таблица/данные),
      экспорт в CSV с учётом прав и фиксацией в логе доступа.

  • Поездки (история поездок)
    — Список поездок (сессии зажигания): ТС, начало/конец, длительность, пробег,
      средняя скорость, количество алертов; детальная страница поездки с треком на карте.

  • Профиль и настройки учётной записи
    — Просмотр и изменение имени, email, телефона, уведомлений; смена пароля;
      блок «Безопасность» с настройкой и отключением 2FA.

  • Управление доступом и роли (для администратора)
    — Список пользователей, смена роли, аудит (лог действий: смена ролей,
      удаление данных, экспорт). Экспорт отчётов доступен только пользователям с правом экспорта.

  • Политика конфиденциальности и защита данных
    — Текстовые страницы: какие данные собираются, цели обработки, сроки хранения,
      меры защиты (шифрование, роли, аудит, удаление по политике), права пользователей.

  • API приёма телематики
    — Внутренний API (/api/telematics/ingest/): приём пакетов телеметрии и алертов
      от генератора данных по ключу (X-API-Key); запись в БД без доступа с фронта.

  • Генератор телематических данных
    — Отдельный Python-скрипт (и/или management-команда) для имитации потока
      телеметрии и алертов без реальных датчиков (см. раздел 6).

  • Политики хранения данных
    — Настройка сроков хранения телеметрии, алертов, поездок, логов в админке;
      команда apply_retention_policies для автоматического удаления устаревших данных.

3. КАКИЕ ФУНКЦИОНАЛЫ ОСОБЕННО РАСКРЫВАЮТ ТЕМУ
═══════════════════════════════════════════════════════════════════════════════

  • Интеллектуальный мониторинг:
    — Карта с позициями ТС и поездки с треками показывают «интеллектуальное»
      использование пространственных и телематических данных.
    — Алерты (скорость, торможение, топливо, геозона, перегрев) демонстрируют
      автоматическую обработку событий и информирование.
    — Отчёты (пробег, топливо, алерты) показывают аналитику на основе телеметрии.
    — Дашборд даёт единую точку входа и сводку состояния парка.

  • Защита телематических данных:
    — Шифрование VIN и номера ВУ в БД и маскирование при выводе — защита
      персональных и идентификационных данных на уровне хранения и отображения.
    — Роли и проверка прав (в т.ч. на экспорт) — разграничение доступа к данным.
    — Аудит (AccessLog): кто, когда и какое действие выполнил — подотчётность
      и соответствие требованиям к учёту доступа к персональным данным.
    — Политика хранения и команда удаления старых данных — минимизация хранения
      и соблюдение сроков, заявленных в политике конфиденциальности.
    — 2FA — усиление защиты учётной записи и доступа к системе.
    — API приёма данных с ключом — защита канала поступления телеметрии от
      несанкционированного доступа.
    — Страницы «Политика конфиденциальности» и «Защита данных» — прозрачность
      и информирование пользователей, что важно для соответствия GDPR и аналогичным требованиям.

В дипломе можно отдельно выделить главы/параграфы: «Реализация мониторинга» (карта,
алерты, отчёты, поездки) и «Реализация защиты телематических данных» (шифрование,
роли, аудит, политика хранения, 2FA, API).

4. АКТУАЛЬНОСТЬ, ЦЕЛЬ И ЗАДАЧИ ПРОЕКТА
═══════════════════════════════════════════════════════════════════════════════

  Актуальность
  ------------
  • Рост спроса на системы мониторинга транспорта (логистика, такси, корпоративный
    автопарк, безопасность) и на телематические сервисы.
  • Ужесточение требований к обработке персональных и телематических данных
    (GDPR, локальные законы о персональных данных), необходимость не только
    собирать данные, но и защищать их.
  • Сочетание «мониторинг + защита данных» в одном проекте позволяет продемонстрировать
    современный подход к разработке таких систем и даёт практическую ценность для диплома.

  Цель проекта
  ------------
  Разработать учебно-демонстрационную веб-систему интеллектуального мониторинга
  транспорта (SafeTrack) с акцентом на защиту телематических и персональных данных,
  включающую приём, отображение и анализ телеметрии, карту, алерты, отчёты, поездки,
  управление доступом и реализацию мер защиты (шифрование, аудит, политика хранения, 2FA).

  Задачи проекта
  --------------
  1. Проанализировать рынок и аналоги (Geotab, Wialon, Samsara и др.), требования
     к защите телематических данных.
  2. Спроектировать структуру системы: модули (учётные записи, транспорт, телематика,
     карта, отчёты, поездки, настройки), модели данных, роли и права.
  3. Реализовать приём и хранение телематических данных (в учебной постановке —
     с использованием генератора данных).
  4. Реализовать отображение данных: дашборд, карта позиций ТС, карточки ТС,
     алерты, история поездок, отчёты с экспортом.
  5. Реализовать меры защиты данных: шифрование чувствительных полей (VIN, номер ВУ),
     разграничение доступа по ролям, аудит действий, политика хранения и удаление
     устаревших данных, двухфакторная аутентификация, защищённый API приёма данных.
  6. Реализовать пользовательский интерфейс: регистрация, вход, профиль, настройки
     учётной записи и (для админа) управление пользователями и ролями.
  7. Обеспечить прозрачность обработки данных: страницы политики конфиденциальности
     и защиты данных.
  8. Подготовить описание проекта и обоснование выбора решений для дипломной работы.

5. ИСПОЛЬЗОВАННЫЕ ТЕХНОЛОГИИ
═══════════════════════════════════════════════════════════════════════════════

  Backend
  -------
  • Python 3
  • Django — веб-фреймворк, ORM, админка, аутентификация, шаблоны
  • django-otp (TOTP) — двухфакторная аутентификация
  • cryptography (Fernet) — шифрование чувствительных полей в БД

  База данных
  -----------
  • SQLite3 — хранение данных (пользователи, ТС, водители, телеметрия, алерты,
    поездки, лог доступа, политики хранения)

  Frontend
  --------
  • HTML5, CSS3 — разметка и стили (базовые стили в стиле Geotab, адаптивная вёрстка)
  • JavaScript — интерактивность (меню-гамбургер, иконки)
  • Lucide Icons — иконки на фронте
  • Leaflet, OpenStreetMap — карта с маркерами позиций ТС

  Генерация и приём данных
  -----------------------
  • Отдельный Python-скрипт (scripts/data_generator.py) — генерация телеметрии
    и алертов, отправка по HTTP в API (библиотека requests)
  • Management-команда Django (generate_telemetry) — альтернативная генерация
    с записью напрямую в БД
  • REST API (Django, JSON) — приём пакетов телеметрии по ключу (X-API-Key)

  Инфраструктура и инструменты
  ---------------------------
  • Git — контроль версий (при использовании)
  • requirements.txt — зависимости Python
  • Планировщик (cron / Планировщик заданий Windows) — запуск политик хранения
    (apply_retention_policies) по расписанию

6. РАНДОМНЫЕ (ДЕМОНСТРАЦИОННЫЕ) ДАННЫЕ: КАК И ЗАЧЕМ
═══════════════════════════════════════════════════════════════════════════════

  Как мы показываем данные
  ------------------------
  В проекте нет реальных транспортных средств и датчиков (GPS, CAN-шина, датчики
  топлива и т.д.). Поэтому телематические данные (координаты, скорость, уровень
  топлива, зажигание, одометр) и события (алерты) генерируются программно:

  1. Генератор данных (скрипт или команда Django):
     • Транспортные средства задаются в БД (гос. номера, тип, марка, модель и т.д.)
       вручную через админку или создаются командой generate_telemetry.
     • Скрипт «двигает» каждое ТС по заранее заданному маршруту (набор точек
       широта/долгота в районе г. Алматы). За один интервал (например 10 секунд)
       позиция сдвигается вдоль маршрута, добавляется небольшой случайный шум.
     • Для каждой «позиции» формируется запись телеметрии: timestamp, lat, lon,
       speed, fuel_level, ignition_on и при необходимости odometer и др.
     • С заданной вероятностью генерируются алерты (превышение скорости,
       резкое торможение, низкое топливо, простой с зажиганием, выход из геозоны,
       перегрев и т.п.) и привязываются к текущей позиции ТС.
     • Данные либо записываются в SQLite через ORM (management-команда),
       либо отправляются на сервер по HTTP в API /api/telematics/ingest/ (скрипт
       data_generator.py с ключом X-API-Key).

  2. Сайт (Django) не различает источник данных: он читает из БД те же таблицы
     (TelemetryRecord, Alert, Trip и т.д.), что и при работе с реальными датчиками.
     Карта, дашборд, карточки ТС, алерты, отчёты и поездки работают с этими
     записями так же, как с «настоящими» данными.

  Почему мы так делаем
  --------------------
  • Отсутствие оборудования: для дипломного проекта нет доступа к реальным
    машинам, GPS-трекерам и телематическому оборудованию. Генерация данных
    позволяет полноценно продемонстрировать весь функционал системы (карта,
    алерты, отчёты, поездки) без железа.
  • Воспроизводимость и контроль: можно задать маршруты, частоту обновлений
    и типы алертов, чтобы демонстрация была предсказуемой и наглядной.
  • Безопасность и этика: не используются реальные координаты и персональные
    данные людей; все данные синтетические, что упрощает соответствие
    требованиям к защите данных в учебном контексте.
  • Масштабируемость: можно имитировать несколько десятков ТС и поток событий,
    проверяя работу интерфейса и отчётов под нагрузкой.
  • Соответствие теме: акцент диплома — «интеллектуальный мониторинг и защита
    телематических данных». Архитектура системы (приём данных → хранение →
    отображение → защита) остаётся той же; разница только в источнике данных
    (генератор вместо датчиков), что в пояснительной записке достаточно
    описать и обосновать.

  Итог: использование рандомных/сгенерированных данных — осознанный выбор для
  учебно-демонстрационного проекта из-за отсутствия реальных машин и датчиков;
  при этом все сценарии использования системы (мониторинг, карта, алерты,
  отчёты, защита данных) демонстрируются в полном объёме.
